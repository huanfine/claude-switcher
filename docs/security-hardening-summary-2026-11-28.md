## 1. 本次目标

本轮加固解决已经复现或确认的更新 fail-open、账号切换半状态、节点门禁绕过、运行期竞态、快照完整性与 root 权限边界问题，并建立可重复的发布验证。

本次没有改变以下核心安全口径：

- 出口国家与目标不一致时，不启动 Claude。
- 切换账号前必须完全退出 Claude 桌面进程和 Claude Code CLI。
- 硬性安全项不可关闭或降级，`skip` 不算通过。
- 报告是检查快照，租约才是启动许可；环境或核心变化后旧租约必须失效。
- 节点扫描只读，不通过逐节点在线切换采集数据。
- 不改变 `accounts/<A-H>/`、`cli/<A-H>/` 的账号存档结构。
- 不新增第 17 项检查，不改变 16 个稳定检查 ID。
- 不把真实账号、住宅/代理 IP、凭据或 Clash 配置写入测试和文档。

## 3. 关键修复说明

### 3.1 更新链路：从“复制文件”改为可验证事务

更新流程现在为：

1. 拉取候选发布包。
2. 校验工件 SHA256。
3. 确认清单必须包含 `core/claude-switch.sh`。
4. 对候选核心执行 `bash -n`。
5. 在同目录准备候选文件并原子替换。
6. 运行结构化更新自检。
7. 自检失败时恢复旧核心，并验证回滚后的哈希与字节。

更新自检保留反自锁设计：

- 基线 `ok → fail` 或 `ok → config`：回滚。
- 基线已经是 `fail/config/warn/skip`：不因沿用旧状态回滚。
- 新核心首次检出的环境 `fail`：不阻止更新，但必须在结果中点名。
- 自检非零、报告不可解析、稳定 ID 缺失或重复、配置指纹不匹配：属于核心契约失败，必须回滚。

这样既不会安装“根本不会产生可信报告”的坏核心，也不会因为环境本身有问题而阻止能修复环境的新核心安装。

### 3.2 账号切换：桌面版、CLI 与 current 可恢复

一次切换现在覆盖：

- 桌面版实时目录；
- `~/.claude/`；
- `~/.claude.json`；
- 当前槽位记录 `current`。

切换前先完成预检和准备，再写入权限为 0600 的事务日志。提交过程中任何已知失败都会按日志逆序恢复；进程在提交中崩溃时，下次切换会先恢复未完成事务，不会盲目删除无法证明归属的目录。

启动租约也前移到实时状态变更之前，并在最终提交前再次复核，避免“数据已经换了，但启动许可已经失效”的窗口。

### 3.3 节点应用：显式选择与自动推荐同一门槛

`node-apply <leaf>` 不再绕过节点扫描门槛。显式节点和报告推荐节点都会重新校验：

- 出口国家是否符合目标；
- 是否被判为 Tor 或代理特征；
- UDP 能力是否满足当前 WebRTC 策略；
- 是否为出口未知的 CDN 前置节点；
- 是否具有可用评级；
- 执行时 Claude 进程和巡检状态是否允许操作。

执行门禁按实时状态重新判定，不信报告中的旧快照。切换后还会复查出口国家，不达标自动回滚。

### 3.4 watch 代际隔离

App 停止或重启 watch 后，旧一代守护的完成回调和迟到输出不能再清除、失败或重启新一代守护。该修复针对的是运行期竞态，不改变 watch 的出口基线、复检次数和拦截策略。

### 3.5 快照 v2：先认证，再解密，再解压

新导出格式为 `CLAUDE-SWITCHER-ARCHIVE-2`，采用 encrypt-then-MAC：

- 加密：OpenSSL AES-256-CBC。
- 认证：PBKDF2-HMAC-SHA256 派生密钥，HMAC-SHA256 校验。
- 密码通过继承文件描述符传入，不进入子进程 argv 或磁盘。
- HMAC 覆盖规范化 header 和完整 OpenSSL 密文封装。
- 只有认证成功后才调用解密和解压。

解压前会拒绝：

- 绝对路径、`..` 路径和空成员名；
- 符号链接、硬链接、设备文件、FIFO 及其他特殊成员；
- 重复成员和文件/目录路径冲突；
- 超过成员数、单成员大小或总解压大小限制的归档。

解压后还会再次检查目录树，防止归档元数据之外出现链接或特殊文件。marker 必须是普通文件且小于 64 KiB。

v1 归档仅保留迁移导入能力，成功导入后会明确提示“旧格式没有完整性认证”。新导出不会再写 v1。

### 3.6 root 边界：时区目标由管理员授权物化

安装器不再把动态路径、时区和网络服务名拼进 `sudo bash -c` 源码，而是使用静态 root 脚本加位置参数传参。root 侧会在任何系统修改前再次校验安装路径和 IANA 时区。

root 时区看门狗现在只读：

```text
/Library/Application Support/claude-switcher/tz-target
```

该文件由安装器或 `fix` / `set-region` 在同一次管理员授权中原子写入，属 `root:wheel`。看门狗不再直接采纳用户可写的 `env.json`，避免用户配置变化间接触发无需新授权的 root 时区修改。

### 3.7 发布门禁与运行时哈希

Release 工作流现在先调用完整 `checks.yml`，全部成功后才进入打包和发布。tag 发布不能绕过 macOS 与 Windows 的测试门禁。

`SHA256SUMS` 新增覆盖：

- `core/stun-probe.py`
- `scripts/upgrade-core.sh`
- `scripts/diagnose-fix.sh`
- `scripts/diagnose-install.sh`

一体化安装包还会在构建阶段执行包内 `shasum -c`，避免“源码哈希正确，但随包文件缺失或损坏”。

### 3.8 提示、文档与测试卫生

App 的核心回滚提示现在：

- 兼容旧两列记录 `时间|原因`；
- 兼容新三列记录 `时间|core|原因`；
- 不再武断写成“自动更新被回滚”；
- 不再暗示环境修好后一定会自动恢复；
- 只读取普通文件，最大 64 KiB；
- 原因最多展示 240 个字符；
- 文件缺失、损坏或读取失败时清除旧提示。

架构文档删除了容易腐烂的精确行数和测试数量，并同步了 IP 纯净度的六个 HTTP 源、类型证据与风险证据分离等当前口径。

测试资源也完成清理：

- FlClash SQLite 连接显式关闭；
- watch 测试中的子进程显式 `wait()` 回收；
- 没有使用忽略 warning 的方式掩盖资源泄漏。

## 5. 兼容性与升级注意

1. **快照 v2 需要新版导入器。** 旧版本不识别 v2，不能直接降级到旧导入器；应保留新版导入器或使用迁移工具。
2. **root 时区看门狗需要刷新安装态。** 已安装旧看门狗的机器需要在明确授权后重跑安装器，不能由 Agent 私自覆盖系统目录。
3. **核心更新仍信任 GitHub + HTTPS。** 本轮加强了传输与工件完整性校验，但没有引入独立代码签名和密钥轮换。
4. **Windows 真机验收仍未完成。** 本轮通过的是 CI 中的隔离集成测试，不应把 CI 结果表述为 Windows 真机验收。
5. **没有在本机部署。** 维护者的已安装核心、App、守护和真实账号状态均未被本轮修改。

## 6. 回滚方式

- 单个问题修复可以通过 revert 对应提交回滚。
- 核心更新失败使用同目录旧核心备份，回滚后校验哈希；失败时保留备份并明确报错。
- 账号切换失败通过事务日志恢复桌面版、CLI、`current` 和启动调用状态。
- 节点应用失败恢复切换前 leaf；国家复核失败时不继续切账号。
- 快照格式不能简单降级，必须保留 v2 导入能力。
- root 看门狗属于安装态，代码回滚不等于系统目录已回滚；需要用户授权后重跑安装器。
- CI 回滚不能通过跳过检查实现。

## 7. 尚未覆盖的事项

本轮没有实施以下内容，避免把“已加固”表述为“所有风险已消失”：

- PF anchor 或系统级 fail-closed 防火墙；
- 更新独立签名与密钥管理；
- Windows/Linux 防护能力全面补齐；
- IP 纯净度评分模型调整；
- 真实 Windows WPF、FlClash、隔离浏览器和安装更新的真机验收；
- 维护者本机的安装、升级、账号切换和 root 守护真机验收。

这些事项需要单独设计、授权和验证。
